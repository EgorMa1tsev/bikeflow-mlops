# Data contract — BikeFlow

Документ фиксирует, что именно течёт по пайплайну. Любое изменение здесь —
ломающее изменение для API участницы B.

## Источник

| | |
|---|---|
| Датасет | Seoul Bike Sharing Demand, UCI ML Repository (id 560) |
| URL | https://archive.ics.uci.edu/static/public/560/seoul+bike+sharing+demand.zip |
| Файл | `SeoulBikeData.csv`, кодировка **cp1252**, дата **DD/MM/YYYY** |
| Объём | 8760 строк × 14 колонок = ровно один год почасовых наблюдений |
| Период | 2017-12-01 00:00 … 2018-11-30 23:00 |
| Гранулярность | один город целиком, один час. Разбивки по станциям в датасете **нет** |
| sha256 | `373339b71a8935d69e9af0abf26a70744632119862eeb3919efb389a7b749c60`, проверяется до записи |

Качество исходных данных: пропусков нет, дубликатов `(Date, Hour)` нет, часовая
сетка без разрывов.

## Признаки модели

Фиксированный порядок задаётся `params.yaml` и проверяется при загрузке артефакта.

```
категориальные: hour, day_of_week, season
числовые:       temperature, humidity, wind_speed, visibility, dew_point,
                solar_radiation, rainfall, snowfall, is_holiday
```

`month` и `day_of_year` **исключены осознанно**. При временном split train содержит
только месяцы 12 и 1–7, поэтому месяцы 8–11 приходят в модель как уровни, которые
никогда не получали градиента. Сезон плюс погодные колонки несут ту же информацию
в форме, переживающей разбиение. Замер: удаление `month` улучшило validation MAE
основной модели с 219.1 до 168.7.

Лаговых признаков таргета нет. Одно наблюдение самодостаточно.

## Правила, на которые опирается код

1. **Закрытые часы.** `is_functioning == False` ⟹ `rented_bike_count == 0`, всегда.
   В данных таких часов 295, и все они строго нулевые; среди рабочих часов нулей нет.
   Следствия: такие часы исключаются из обучения и метрик, а на инференсе прогноз
   перезаписывается нулём **в обход модели**. В `data/processed/*.parquet` они
   сохраняются — нужны для replay на этапе 5.
2. **Неотрицательность.** Прогноз всегда `>= 0` (softplus на выходе плюс явный clip).
3. **Сезоны.** Ровно четыре известных значения, иначе `DataContractError`.
4. **Часовая сетка.** Разрывы и дубликаты `timestamp` считаются ошибкой данных.

Все четыре проверяются в `bikeflow.data.preprocess.validate()` и покрыты тестами.

## Контракт запроса на предсказание

Обязательные поля: `date` (**ISO, YYYY-MM-DD**), `hour`, `temperature`, `humidity`,
`wind_speed`, `visibility`, `dew_point`, `solar_radiation`, `rainfall`, `snowfall`,
`season`.

Необязательные: `is_holiday` (по умолчанию `false`), `is_functioning` (по умолчанию `true`).

Диапазоны, типы, единицы и API-имена — в `FEATURE_CONTRACT`
(`src/bikeflow/ml/features.py`),
это единственный источник правды. Нарушение → `FeatureValidationError` с именем поля.

Формат даты строго ISO: `01/12/2018` отклоняется, потому что при разных соглашениях
это либо 1 декабря, либо 12 января, и угадывать здесь нельзя.

## Временное разбиение

| Split | Период | Строк | Рабочих часов | Средний спрос | Сезоны |
|---|---|---|---|---|---|
| train | 2017-12-01 … 2018-07-31 | 5832 | 5784 | 645.0 | Winter, Spring, Summer |
| validation | 2018-08-01 … 2018-09-30 | 1464 | 1368 | 968.9 | Summer, Autumn |
| test | 2018-10-01 … 2018-11-30 | 1464 | 1313 | 850.3 | только Autumn |

**Ограничение.** Датасет покрывает ровно один год, поэтому сезоны по выборкам не
пересекаются равномерно, а средний спрос смещён между сплитами. Test — только осень,
и сезон `Autumn` вообще отсутствует в train. Это неизбежное свойство временного
split на годе данных, а не ошибка разбиения; «чинить» перемешиванием нельзя, это
внесло бы утечку.

Практические следствия:
- абсолютные MAE между сплитами несравнимы, сравнивать надо WAPE;
- сезонный срез на test вырождается в один сезон, поэтому на test смотрим срезы
  по часу, выходным и осадкам;
- уровень `season = Autumn` нейтрализуется в нейросети (обнуляется), чтобы прогноз
  не зависел от случайной инициализации. См. `TorchMLPRegressor.neutralise_unseen`.
